# SNHU_CS250_Sprint_Review_and_Retrospective

## Reflection

### How do I interpret user needs and implement them into a program? How does creating user stories help with this?

I start by listening to what the user is actually trying to accomplish, not just the feature they ask for. On the SNHU Travel project, the client's interview was turned into user stories that each captured who the user is, what they want, and why. Writing stories this way kept the focus on value to the user instead of technical details. Each story also had acceptance criteria, so developers and testers shared the same definition of "done." When the client changed direction to wellness and detox vacations, the stories made it easy to see what needed to be rewritten, removed, or reprioritized.

### How do I approach developing programs? What Agile processes do I hope to incorporate into my future development work?

I approach development in small, testable pieces. I would rather build a working slice, get feedback, and adjust than build everything at once and find problems at the end. Going forward, I want to keep using:

- **A prioritized backlog**, so the most valuable work gets done first
- **Short sprints**, so changes in direction cost days, not months
- **Testing within each sprint**, so defects are caught while the code is still fresh
- **Daily stand-ups**, to surface blockers early
- **Retrospectives**, to improve the process as well as the product

### What does it mean to be a good team member in software development?

Being a good team member means communicating clearly, asking questions instead of guessing and owning my part of the work while understanding everyone else's. Rotating through the Product Owner, Developer, Tester, and Scrum Master roles in this course showed me how much each role depends on the others. A good teammate keeps others informed, stays open to feedback and change, and puts the team's goal ahead of personal preferences. It also means respecting the process, such as showing up prepared to stand-ups and being honest in retrospectives, because that is what keeps the whole team moving forward.
